## 4. Идемпотентность (ключевая проверка ТЗ)

Один и тот же `request_key` отправлен дважды на расходуемый предмет:

```json
{
  "first":  { "s": 200, "replayed": false },
  "second": { "s": 200, "replayed": true, "msg": "Предмет уже использован" }
}
```

Состояние после двух вызовов: предмет 4 отсутствует, предметы 1–3 не изменились.

**Вывод:** повторная операция не выполняет побочный эффект дважды. Движок не может
«некорректно повторить» игровое действие.

Отдельно проверено на уровне клиента: на одно нажатие приходится **ровно один POST**
(перехват сети: `GET list`, `POST`, `GET list`).

## 5. Негативные сценарии

| Сценарий | Ожидалось | Получено |
|---|---|---|
| Неверный CSRF | 400 | **400** «Некорректный запрос» |
| Несуществующий предмет (`id=999`) | 404 | **404** «Предмет не найден» |
| `use` на нерасходуемом предмете | 409 | **409** «Этот предмет нельзя использовать» |
| `equip` на расходуемом предмете | 409 | **409** «Этот предмет нельзя экипировать» |
| Изменяющее действие через GET (`?action=use`) | 400 | **400** «Неизвестное действие» |
| API без сессии | 401 | **401** «Сессия игрока не найдена» |

Fail-closed поведение подтверждено: неавторизованный вызов не изменяет состояние.

## 8. Воспроизведение

```powershell
cd F:\codex-hybrid-engine
.\.venv\Scripts\python.exe tools\visual_qa_inventory.py
```

Скрипт сам поднимает PHP-сервер на `127.0.0.1:8791`, сбрасывает **только**
временный fixture состояния (`%TEMP%\codex-hybrid-engine-demo-*`), прогоняет
проверки, сохраняет скриншоты и JSON-доказательство, затем останавливает сервер.
Файлы проекта при этом не изменяются.
